## Video feed and administration

The public feed in `index.html` reads documents from the Firestore `videos` collection where `admin` is `"yes"`. Each document uses its Firestore document ID as the video ID and supports these fields:

- `link`: Cloudinary video URL
- `mediaType`: `"video"` or `"image"`; older documents without this field are treated as videos
- `description`: video caption
- `likesCount`, `savesCount`, `sharesCount`: numeric counters
- `comments`: array of comment strings or comment objects; comment objects may include `username`, `userId`, `text`, and `profileImageLink`
- `uploadedBy`: creator name
- `profileImageLink`: Cloudinary profile-image URL
- `admin`: `"yes"` to include the video in the public feed

## Superadmin

Open `superadmin.html` to upload and manage media. The sign-in page compares the entered `username` and `password` with the `admin/login` Firestore document. Admin uploads saved as drafts use cloud `hjkjnzpz` and preset `pending_review`; publishing transfers those assets to cloud `s35mxosr` using preset and folder `user_uploads`. Admin uploads published immediately go directly to the publishing cloud.

The admin page manages every field listed above, including counters, comments, and published/draft visibility. Its Users tab lists follower/following totals, allows editing all fields in a user's private document, and provides a verification toggle. Verification is stored as `"yes"` or `"no"` in both `users/{uid}` and `profiles/{uid}`; public badges read the public profile value. The raw user-field editor represents Firestore timestamps with a `$firestoreTimestamp` ISO-date marker. Deleting a video removes its Firestore document; the unsigned Cloudinary configuration cannot delete the uploaded asset. Its credential check runs in the browser and is only a UI gate; it does not secure Firestore. Do not rely on it for authorization. Protect the database with restrictive Firestore Security Rules and a server-enforced authentication design before using it with sensitive or production data.

## User accounts and feed activity

Users can browse and scroll the public feed without an account. Liking is also available while signed out; comments and other feed actions send users to `oauth.html` to log in or register. Email/password authentication must be enabled in Firebase Authentication. Registration stores private account details (including email and phone) in `users/{uid}`, creates a public profile at `profiles/{uid}`, and reserves lowercase usernames in `usernames/{usernameLower}`. Public profiles contain `fullName`, `username`, `usernameLower`, `profilePic`, `bio`, and `pinnedVideos`; liked/saved video IDs are stored on the owner's private user document. Signed-in users can upload photos or videos from their device or capture media from a camera in the create modal. Submissions upload to cloud `hjkjnzpz` using preset `pending_review`, then save in `videos` as drafts (`admin: "no"`) with zero counters and the user's username/profile picture.

When an admin publishes a creator draft, the source image or video is copied to cloud `s35mxosr` using preset and folder `user_uploads`; Firestore is updated to the new URL and the video is published only after transfer succeeds. Cloudinary assets uploaded to the review cloud are not automatically deleted after transfer.

Feed interactions are recorded as documents in `activity` with `videoId` and/or `profileId` when relevant, `userId`, `action`, `details`, and `createdAt`. Profile visits are recorded for the profile owner's viewer list. Follow relationships are stored in `follows` documents keyed by follower/followed user IDs, with `followerId`, `followingId`, and `createdAt`; follow and unfollow actions are also recorded in `activity`. Profile follower/following totals are computed from these relationship documents. Profile likes total the `likesCount` values of the user's published videos. Likes, saves, and shares update `likesCount`, `savesCount`, and `sharesCount` on the corresponding `videos/{videoId}` document; signed-in likes/saves also update the owner's private ID lists. Comments include the author's username, user ID, and profile picture; opening a commenter with a stored username leads to `view-profile.html?username=…`. A commenter without a username is shown as profile locked. Creator verification badges appear in feed posts, comments, profile pages, and the profile video viewer when `profiles/{uid}.verify` is `"yes"`. When admins save video comments, usernames are checked against `users`; missing commenters are created as Firestore user/profile documents and their usernames are reserved, with the video and commenter records committed together. Admins can edit comments and upload commenter profile images, and manage public user profile details and images in `superadmin.html`. The admin dashboard also displays the latest 100 activity records. Profile video cards open a full-screen, vertical snap-scrolling viewer. Signed-out likes use a locally generated guest identifier. Configure Firestore Security Rules to allow public reads of published videos, `profiles`, and follow counts; restrict follow creation/deletion to the authenticated follower; validate activity writes and counter changes; reserve usernames safely; and restrict `users` documents to their owner. Client-side UI checks are not authorization.
